# 863 继续探索：冻结模拟器逐行复读与同周期写入（2026-10-27）

**可执行最好成绩仍为 864 cycles，本轮没有得到 863 程序。**

此前的结论都依赖对模拟器语义的理解。本轮逐行复读 `tests/frozen_problem.py`
的 `run`、`step`、`alu`、`valu`、`load`、`store`、`flow`，并在冻结模拟器上实测
关键细节。

## 1. 复读确认的语义

| 项目 | 语义 | 对优化的意义 |
|---|---|---|
| 计周期 | 指令字典含任一非 `debug` 键即计 1 周期，与槽是否为空无关 | 只含 `debug` 的指令不计周期，但测试关闭调试，它什么都不做 |
| 读写时序 | 所有读取看周期开始时的 scratch 与内存；写入在周期末统一提交 | 本周期写的值最早下周期可用，首尾界成立 |
| 同周期多写 | `scratch_write`/`mem_write` 是字典，按指令中引擎的书写顺序、再按槽序覆盖 | 见第 2 节 |
| 越界 | scratch ≥1536 或内存 ≥2566 在提交时抛异常；负 scratch 下标别名到末尾 | 没有额外存储 |
| ALU 运算 | Python 大整数计算后取模 2^32；`<<` 大移位量会生成巨大整数 | 移位量必须小 |
| 除零 | `//`、`%`、`cdiv` 遇 0 抛异常 | 除法只能用非零常量或已知非零值 |
| `halt`/`pause` | `halt` 停核；测试中 `pause` 无效 | 提前停核会漏写输出 |

## 2. 同周期覆盖：实测与评估

实测（冻结模拟器）：

- 同一周期 `load` 与 `alu` 写同一字，字典中排在后面的引擎胜出：先 load 后 alu
  得 alu 的值，反之得 load 的值。
- 与重叠 vload 同周期的 ALU 自拷贝 `x | 0`，能保住被 vload 覆盖位置上的旧值
  （“写保护”）：窗口 `[100,108,102,110,…]` 中 102 被保留。

这是一种此前没有系统考察的手法：每保护一个字花 1 条 ALU。它能否突破现有界限：

- **选择车道引理不受影响。** 引理的矛盾是同一 scratch 字要同时存 `R_e` 与
  `L_{e+1}` 两个不同的值，与写入先后无关。
- **合并两次半选择。** 第二次半选择的同周期内用 4 条 ALU 自拷贝保护第一次的有效
  车道，可得完整的 8 车道结果，节点异或改用 1 条 VALU（8 lane）；但现行做法是
  8 条 ALU 直接读跨步结果，同为 8 lane，合并反而多 4 lane。
- **混合 VALU 结果与载入值。** 只是把两条本来就要执行的指令写进同一向量，不省
  算术。

## 3. 数据相关的捷径

- 若根节点满足 `R ^ C5` 属于“仿射兼容异或常数”集合，第 11 轮的根节点异或可并入
  MAD0，省 256 lane；但这要求 `R = 0x355a4f09` 之类的特定值，概率约 2^-30。
- 内核在构建时只拿到规模参数；测试用 `lru_cache` 对 8 次正确性测试和计时复用同一
  内核，按某组数据专门化的程序在其他数据上会出错。
- 依赖“随机值很少碰撞/进位”的近似计算不是正确程序，未采用。

## 4. 结论

模拟器没有可合法利用、能省算术的语义；同周期写保护是真实存在的手法，但每个字
要 1 条 ALU，在现有图中没有净收益。
