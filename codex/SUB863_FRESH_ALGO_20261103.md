## 1. 逐周期实测（独立重测，非照抄账本）

直接在冻结模拟器上对提交内核逐包统计算术 lane（`alu`=1/slot，`valu`=8/slot，
容量 60 lane/cycle）：

```
总容量 864 × 60 = 51840，实际算术 C = 51665，浪费 175
  首部 c0            = 52  （scratch 全 0，唯一有用产物是一条全 1 向量 8 lane）
  中段 c676–c742     =  7  （调度零头，5 个欠载周期）
  尾部 c861/862/863  = 12 + 44 + 60 = 116
LOAD 1688（末次 c849）  FLOW 851（末次 c853）  STORE 530（末次 c863）
```

863 × 60 = **51780**。排进 863 需 `C + 首部浪费 + 尾部浪费 ≤ 51780`；当前
`51665 + 52 + 116 = 51833`，**差 53 lane**。中段那 7 lane 即使调度到 0 也无济于事
（51833 → 仍 864）。故唯一出路是把算术工作 C 砍掉 53 lane。

首部 52、尾部 116 的结构性不可避免已在既有笔记中证明，本轮实测完全吻合：
- 首部：c0 时 LOAD 刚发出的数据下一周期才回来，VALU/ALU 只能产常量 0/1，
  有用的至多一条全 1 向量（8 lane）。
- 尾部：最后周期只能是 STORE（store 读上一周期 scratch，本周期算术无人消费）→
  60 浪费；T−1 的算术只能喂 T 的两条 vstore（≤16 lane）→ ≥44；T−2 ≤48 → 12。

## 2. 哈希是与算法无关的硬地板

256 元素 × 16 轮 = **4096 次哈希求值，不可省任何一次**：每轮输出依赖上一轮
（非线性双射，不可展开化简），元素间输入互异（32 位随机，碰撞可忽略），
无共享。每次哈希严格 10 条算术（右移必须独占一条；`(a^C1)^(a>>19)` 要把
{a, C1, a>>19} 三值异或到一起，而 ISA 无三输入 XOR，`multiply_add` 是乘加非异或，
故 ≥3 条——与既有逐 stage 证明一致）。

$$4096 \div 8 \text{ lane} \times 10 \text{ op} \times 8 = 40960 \text{ lane}$$

占 C 的 79%。于是导航开销必须 `≤ 51612 − 40960 = 10652`，当前
`51665 − 40960 = 10705` → **必须且只能从导航里砍 53 lane**。导航各项（按组逐操作码
统计，全程）：节点异或 4096（每轮 `val^node`，强制）、奇偶位 3584（14 次/元素）、
gather 地址 1536（6 次/组）、C5 管理 1279（预异或 511 + d9/d10 恢复 512 + 输出 256）、
指针/常量/杂项 ~210。每项均已被既有研究证到按深度/逐操作码最优。

## 3. 几种"全新结构"的定价（均为必要成本估算，非实测分数）

| 思路 | 结论 |
|---|---|
| **位切片 bitslice**（1 向量 = 256 元素的同一位） | 全 32 位 XOR = 32 向量 op（与现状持平），移位变免费；但一次 32 位 ripple-carry 加 ≈ 每位 5 op × 32 = 160 向量 op，而现 MAD 仅 32 op/全 256 元素 → **加法 5× 恶化**。哈希含约 6–8 个等效加法，整体 ≈3× 更差 |
| **广度优先 / 按节点聚合** | 元素按随机哈希位发散到不同叶子，按节点聚合需数据相关 scatter/排序，更贵 |
| **查表 / 数论表示（Montgomery 等）** | 哈希输入 32 位随机不可表；+、^、<<、>> 混合，无单一表示同时降低两类运算 |
| **跨轮 / 跨元素代数合并** | 哈希为复杂非线性双射，复合不化简；根节点、C1、C5 并入相邻 stage 已被 396,249 连线 CEGIS 判死 |

## 4. 最接近的一次：三层记录（52/53 + 断链）

唯一值得认真定价的全新路线：把记录从 2 层（节点+2 子）扩到 3 层
（节点+2 子+4 孙，占满 8 字一向量），让 d3 的一次 gather 覆盖 d3/d4/d5，
省掉 d5 的地址 MAD。

- **省**：d5 地址 MAD ~8 lane/组 × 7 组 = **56 ≥ 53 arith**，并释放 56 个 LOAD；
- **代价**：d5 四选一需 +2 FLOW/组（用 bit3 选孙辈对、bit4 选最终），×7 = **+14 FLOW**；
  FLOW 当前 851、863 上限 863、**余量仅 12**，超 2；
- 将 2 个 vselect 改回算术（`b + bit*(a−b)`，1 FLOW → 2 arith）可压回 FLOW=863，
  但净省落到 **52 lane——差最后 1 lane**；
- **致命伤**：3 层记录 8 字已满，装不下 d7 寻址所需的 anchor（第 9 字）。d5 不再
  gather，`p7 = mad(digit, 4, anchor)` 这条链断裂，必须补一次 gather/算术 ——
  把省下的 53 吐回去。

这与 `SUB863_STRUCTURAL_AUDIT_20261023.md` 的"3 层记录需额外 FLOW 或镜像内存、
d9 地址仍依赖被 gather 的值"同源；本轮从零独立推导复现，并精确到
"52/53 + anchor 断链"的临界点，是 864 之紧的最强佐证。

## 5. 结论

三资源（算术、LOAD、FLOW）同时顶在地板，唯一有余量的是 STORE，而 STORE 写出的
数据必须靠 LOAD 读回才有用——LOAD 无余量，故 STORE 余量不可用。这条约束与算法
无关：任何"逐元素走树"的结构都逃不掉深层 d9/d10 的 512 次 per-element gather。

本轮未找到突破 864 的全新算法；并给出独立于原研究的理由相信本族不存在。仍开放
的只剩两条已被大面积穷举封死的极窄缝：
1. 含右移/除法/跨轮 live 值、SMT 尚未覆盖的新哈希改写（省任意 1 op/轮 = 4096 lane）；
2. "STORE 换算术且不吃 LOAD"的新访存原语（本 ISA 下不存在）。

以上均为必要成本估算与下界论证，不是新程序的实测分数，也不构成对任意算法的
全局最优证明。
