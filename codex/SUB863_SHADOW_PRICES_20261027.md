# 863 再审视：每组指令账本与资源影子价格（2026-10-27）

**可执行最好成绩仍为 864 cycles，本轮没有得到 863 程序。** 本文把 864 图拆到
每组（8 个元素）逐条指令，并给出 FLOW、LOAD 换算成算术 lane 的买卖价格。
结论是：已知所有替代方法里，释放一个 FLOW/LOAD 的最低代价高于用它能省下的
最高算术量，因此不存在可以凑出 53 lane 的交换组合。

## 1. 864 图的精确账本

用 `r864.ir.pkl` 按标签统计（与冻结程序逐操作码计数一致，合计 51,665 lane）：

| 部分 | 每组向量指令 | 全程 lane |
|---|---:|---:|
| 哈希（16 轮 × 10） | 160 | 40,960 |
| 节点异或（16 轮） | 16 | 4,096 |
| 奇偶位（12 个 `&1`/`\|~1` + d9/d10 两个） | 14 | 3,584 |
| gather 地址（d3、d5、d7、d9、d10、r14） | 6 | 1,536 |
| C5 恢复（d9、d10） | 2 | 512 |
| 输出 C5 | 1 | 256 |
| **每组合计** | **199** | **50,944** |
| C5 预异或（d0–d8 共 511 节点） | — | 511 |
| 指针、常量及杂项 | — | 210 |

每组还用 26 条 FLOW：d1 1、d2 3、d3 地址 2、子节点选择 2×4（d4、d6、d8、r15）、
d5 地址 1、d7 地址 2、d9 地址 3、r12 1、r13 3、r14 地址 2。

冻结程序的空闲分布：

- 算术：第 0 周期 52、中段共 7（676–742 周期）、末三周期 12/44/60。
- FLOW：全程只空 13 个槽，除第 781 周期外都在第 849 周期之后。
- LOAD：只空 40 个槽，都在第 834 周期及以后。
- 全部 13 条构造向量常量的 VALU 指令（全 1、6 次 vbroadcast、4097 的 MAD、
  5 条 `+`/`*`/`-`）都在第 0–3 周期；ALU 指针加法在第 46 周期前结束。

## 2. 影子价格

**释放资源的代价（买入价）**，按每释放一个单位需增加的算术 lane 计：

| 来源 | 变化 | 每单位代价 |
|---|---|---:|
| d7 数位 `select(b5,select(b6,3,2),b6)` → `2*b5+b6` | +8 lane，−2 FLOW | 4 / FLOW |
| d9 的 k 三选择 → `(r&1)\|1028` 与 `MAD(b7,-2,·)` | +16 lane，−3 FLOW | 5.33 / FLOW |
| d7 地址改双线性链、去掉锚点（d9 地址补一条） | +8 lane，−1 FLOW，−1 LOAD | 4 / 单位 |
| d1/d2/d3/d5 的常量选择 → MAD 插值 | +8 lane，−1 FLOW | 8 / FLOW |
| d5 锚点：vload 后立即用 ALU 复制成连续向量 | +8 lane，−1 LOAD | 8 / LOAD |
| 子节点选择：步长 1 窗口取左子向量，右子节点在被覆盖前用 8 次 STORE 存出再 vload | −1 FLOW，+1 LOAD | 两者 1:1 互换 |

锚点不能用已知掩码 vselect 合并：步长 2 布局中，记录 `2i` 的第 3 字与记录
`2i+2` 的第 1 字同址，按递增顺序装入后只有最后一条记录的高位字幸存，其余锚点
必须在下一次 vload 前读走（现行做法是立即 STORE）。

因此释放一个 FLOW 或一个 LOAD 至少都要 4 lane。

**使用资源的收益（卖出价）**：

| 去向 | 每单位节省 |
|---|---:|
| 向量常量改为 STORE/重读或三字 FLOW 广播 | 名义 6–8 lane，实际 0：这些常量都在第 0–3 周期，那时 VALU 没有其他可做的工作 |
| 指针改用 `add_imm` 或 `const` | 1 lane |
| 现有算术选择改为 vselect | 无：图中已没有算术实现的选择 |

最高卖出价 1 lane 低于最低买入价 4 lane，所以任何以 FLOW/LOAD 为中介的交换
都是净亏损。这把 `SUB863_LOWER_BOUND_ARGUMENT_20261027.md` 第 4 节的交换率顶点
具体化为一对价格，并说明为什么 51,646/51,632/51,612 这类低工作量图只会把浪费
挪到首部：它们省下的正是那 13 条“免费”的首部常量指令。

## 3. 本轮新增的否定结果

- **记录内两字段同时转置不可能。** 每元素一次 vload 时，若左、右子节点向量分别
  位于 `P_L..P_L+7` 与 `P_R..P_R+7`，则 `P_R-P_L` 等于两字段在记录中的距离，
  只能在 1..7 之间，两个窗口必然重叠；重叠位置须同时保存 `L_j` 与 `R_{j-d}`，
  对一般数据矛盾。任意置换元素与车道也不改变此结论。所以子节点选择要么两次
  半 vselect，要么多一次 LOAD。
- **d9 地址免 FLOW。** `p9 = 1028 + p8 - 2*b7 - p7` 有三个逐元素输入加一个常量，
  单个 MAD 吃不下常量 1028：`|0xfffffffe` 只能给出 `p8-2`，常量也无法折进
  `p7`（d7 gather 仍要原始 `p7`），或折进 vload 字偏移（只能偏 0..7）。
  最少多两条 VALU。
- **把记录改到不冲突的“对齐”位置。** 若想让 `p9` 不含常量，d7 记录区必须与 d9
  原始节点区按 `p7` 一一对齐，而两区都长 512 字、彼此紧邻，只能重叠。
- **末轮投机。** 对最后一组同时计算两个子节点的第 15 轮哈希，最后用 FLOW 选择，
  T−1 的有效算术从 16 降到 8，且每组多 12 条指令，更差。
- **第 0 轮的 30 位输入。** x=1 在定义域内，迫使乘数仍为 4097；`c*=g19(C1)`
  的低位非零，在 `4097x+C0` 的取值范围上 XOR 不等于加常数，没有额外自由度。
- **第 0 周期多产 0/1 掩码。** 864 程序已用全 1 向量与相邻零字构成
  `[1,1,1,1,0,0,0,0]` 等掩码窗口，不需另行构造。

## 4. 结论

864 图在三种资源上同时饱和，且已知方法之间不存在有利的交换价格。863 仍需要
一种新原语：每元素每轮省一条运算，或以 STORE（唯一有大量余量的资源）换取
算术而不消耗 LOAD。本轮没有找到这样的原语。
