# 863 赌一把：首段哈希的完整三指令语法与第 0 轮 30 位定义域（2026-10-28）

**可执行最好成绩仍为 864 cycles，本轮没有得到 863 程序。**

此前对哈希首段（C1 所在段）的排除都是具体形式族：两端仿射重编码 63 种
（`SUB863_REENCODING_RIGIDITY_20261027.md`）、与原输入组合 124 种
（`SUB863_FLOW_SINK_20261027.md`）、两指令 406 个模板（`SUB863_HASH_RESEARCH_20261023.md`）。
本轮把它推进到**完整的三指令语法**：除 `vbroadcast` 外的全部 VALU 运算、任意 SSA
连线、任意常量。并且首次在第 0 轮真实的 30 位输入域上做穷举。

## 1. 问题

每轮哈希的首段把节点异或后的 x 变成中段 F 的输入，共 4 条指令：

```text
x --MAD0--> a --(a>>19, ^, ^C1)--> y = g19(4097x + C0) XOR C1 = T(x)
```

两端可以免费改写：

- **输入**：节点预异或能把任意异或常数 e 移到 x 上；d9/d10 的 C5 恢复同样可以带上 e。
  本轮枚举对 MAD0 仿射兼容的 4 个 e：0、2^31、2^32−1、2^31−1，求解器在其中任选。
- **输出**：F 的两条 MAD 能吸收 y 的任意奇数仿射像 `m·y + c`。

若存在三条指令的程序 P，使 `P(x XOR e) = m·T(x) + c` 对所有 x 成立，则每元素每轮
省一条 VALU，全程 4,096 lane，远多于 863 所需的 53。

**第 0 轮。** 第 0 轮的哈希输入是“输入值 XOR 根节点”，两者都由
`random.randint(0, 2**30 - 1)` 生成，所以 x < 2^30，程序只需在 2^30 个输入上正确。
哪怕只在第 0 轮省一条，也有 256 lane，已超过 53。此前笔记只定性讨论过 30 位输入
（`SUB863_FRESH_PASS_20261027.md`、`SUB863_SHADOW_PRICES_20261027.md`），没有做语法
搜索。第 0 轮的根节点向量可带任意键；本轮枚举在该定义域上作用为仿射的 8 个键
`t·2^30` 与 `t·2^30 + (2^30−1)`（t = 0..3），每个键单独求解。

## 2. 语法与剪枝

实现为 `grammar3_head863.py`。

- **操作码**：`+ − * ^ & | << >>` 与 MAD；扩展部分再加 `// % cdiv < ==`。
- **操作数**：输入、任一更早结果或自由常量。移位量可以是常量（0..31）或运行时值，
  按模拟器语义，移位量 ≥32 时结果为 0；除数为 0 时程序无效（模拟器抛异常）。
- **合并**：单数据操作数的仿射形式（x+K、x−K、K−x、x*K、x<<K）都包含于
  `MAD(x,K1,K2)`；`a+b`、`a−b`、`K*a+b` 包含于 `MAD(a,K,b)`；`a*b` 包含于 `MAD(a,b,K)`。
  共 46 种指令形式；测试逐一与未修改的冻结模拟器对照。
- **剪枝**（均可证明不丢解）：
  - 每条指令都被使用。死代码等于更短的程序，可借恒等 MAD 嵌入本语法。
  - 至少含一个非 T 函数的运算：T 的第 0 位依赖输入第 19 位，T 函数的复合做不到。
  - 末条不是会被输出编码吸收的仿射。
  - 全域情形下还删去三类：末条不可能为双射（常量右移、与/或常量、平方、移位常量、
    `%` 与比较）；只经非单射一元值依赖输入；以原输入为除数（u=0 时除零）。
    第 0 轮只需在 2^30 个输入上单射，不用这些规则。

| 范围 | 模板数 |
|---|---:|
| 全域，基本操作码 | 6,072 |
| 全域，加 `// % cdiv < ==` | 20,849（其中新增 14,777） |
| 第 0 轮，基本操作码 | 9,394 |

求解采用 CEGIS：z3 位向量求解器先在 20 个样本上求常量，候选再用 4,096 个随机输入
检验，最后用编译的 C 程序对全部 2^32（第 0 轮为 2^30）个输入穷举核验；反例回填。
**样本集上 UNSAT 即排除该模板的全部常量选择。** 未知乘数 m 只与样本的具体目标值相乘，
这一归一化使多数模板在第一轮、0.05 秒内被排除。

## 3. 结果

| 范围 | 键 | 查询 | 求解器 UNSAT | 超时后的处理 |
|---|---|---:|---:|---|
| 全域，基本操作码 | 4 个仿射兼容键，作为未知数 | 6,072 | 6,072 | 无超时 |
| 第 0 轮 | `t·2^30` | 37,576 | 37,567 | 9 个由精确论证排除 |
| 第 0 轮 | `t·2^30 + 2^30−1` | 37,576 | 37,553 | 23 个由精确论证排除 |

三组合计 81,224 个查询，**没有一个有解**。第 0 轮 75,152 个查询中 75,120 个由求解器
判定 UNSAT（含 7 个长时间重跑），其余 32 个由下面的精确论证排除，未留下未决项
（`grammar3_round0_audit863.json`）。

全域基本语法的 6,072 个模板全部在第一轮（20 个样本）被排除，合计 584 CPU 秒，中位数
0.05 秒；最慢的 5 个恰是“MAD → 右移 → 组合”这类自然形式（最长 28 秒）。

第 0 轮的超时（60 秒，机器满载时 z3 的墙钟限时）由 `grammar3_round0_audit863.py`
逐项给出理由：

- **few-values**（11 个）：末条是“常量右移/左移运行时量”，至多 33 种结果，不可能在
  2^30 个输入上单射。
- **drops-bit0**（5 个）：输入只经 `i1 = u >> s` 进入程序。定义域对 `u XOR 1` 封闭，
  s ≥ 1 时 u 与 u^1 必然撞车；s = 0 时等于把 i1 换成恒等 MAD 的同族模板，该模板同键 UNSAT。
- **same-as-key0**（14 个）：键在定义域上是仿射的（u = ±x + 常数），且 u 只进入
  `i1 = MAD(u,K1,K2)`，MAD 吸收键，问题与键 0 的同一模板相同，后者 UNSAT。
- **linear-out**（2 个）：同上，但 u 还是末条 `K*u + w` 或 `K*w + u` 的操作数；u 的符号
  并入 K 或整式取负（m 仍为奇数），常数并入 c。
- **长时间重跑**（限时 1,800 秒单独重跑）7 个，全部 UNSAT：
  `i1 >> (i1 >> s)`（键 `3·2^30`）60 秒；`u*i1 + i2` 在键 `2^31−1`、`3·2^30−1`、
  `2^32−1` 上分别 9、116、62 秒；`i1*i2 + u` 在键 `2^31−1`、`2^32−1` 上分别 303、167 秒；
  `((u >> s)*K + u) >> s'`（键 `3·2^30−1`）68 秒。满载批量时这些都触到 60 秒墙钟限时。


## 4. 对照与测试

`test_grammar3_head863.py` 共 4 项，全部通过（约 25 秒）：

- 46 种指令形式在随机与边界输入（含移位量 32–63、除法边界）上，Python 与 z3 两种
  语义都与冻结模拟器逐值一致。
- 模板计数：6,072 / 20,849 / 9,394。
- 阳性对照：把 C1 换成可吸收的 `g19(2^31)`，标准模板在 13 秒内求得解，并通过
  2^32 全域 C 穷举；真实目标下同一模板 UNSAT。
- C 核验器：正确候选全域、第 0 轮域都通过；除数为 0 时报告 u=0；错误候选给出反例。

另做的对照（`solve`/`solve_domain` 直接调用）：

| 对照 | 结果 |
|---|---|
| C1 = 0，标准模板 | 16 秒得解，求解器选 e = 2^32−1 与 μ = −4097 |
| 第 0 轮域，C1 = g19(2^31) | 31 秒得解 μ = 4097、ν = C0+2^31、s = 19 |
| 除法模板 `a // K` 代替移位，固定 MAD0 常量 | 4.7 秒得 K = 2^19 |
| 同上，只固定 m、c、e | 6.3 秒同时得 MAD0 常量与 K |
| 自由 32 位键，固定 m、c | 6.9 秒得 μ=4097、ν=C0、s=19、e=2^31 |
| `cdiv(a, 2^19)` 代替移位 | UNSAT（与 `a>>19` 不同，符合预期） |

全部放开的除法与自由键对照在 120 秒内未解出：求解器在未知除数、或两个未知数
相乘时很慢。这只影响找解速度，不影响 UNSAT 的有效性；部分固定的对照确认编码正确。

## 5. 未覆盖的范围

- **任意 32 位输入键。** 本轮只枚举仿射兼容键（全域 4 个，第 0 轮 8 个）。完全自由的
  e 让 m 与符号目标相乘，z3 在标准模板上 120 秒仍未判定；改用“只比较低 k 位”的必要
  条件也未在合理时间内返回。直观上非仿射的键只会让 MAD0 之前多一层异或，更难而非
  更易，但这没有证明。
- **四条及以上指令的窗口**，以及把节点异或并入（两个运行时输入）的窗口。第 0 轮若把
  节点异或与首段一起做成 4 条（现为 5 条），也能省 256 lane；这需要四指令语法，
  规模远超本轮。
- **除法与比较。** 加入 `// % cdiv < ==` 后新增 14,777 个模板（全域、4 个键）。以 10 秒
  为限只跑了 317 个就停止：249 个 UNSAT，68 个超时，其中 39 个的末条是两个运行时值相除。
  z3 对未知除数的除法电路很慢；按这个速度全部跑完需约 2.5 小时、8 个核，且仍会留下约
  2,000 个超时，故停止。部分结果在 `grammar3_head863_full_partial_results.jsonl`。
  末条为 `a // b` 时，P 取到 2^31 以上的值必须 b = 1，所以 P 至少在一半输入上等于前两条
  指令的结果 a；要排除这类模板，需要证明“两条指令在一半输入上与 T 相符”也不可能，
  本轮没有做。

## 6. 结论

这次赌的是：首段（C1 所在段）存在三条指令的写法，或至少在第 0 轮的 30 位输入上存在。
任一成立都足以突破 864：全域成立省 4,096 lane，仅第 0 轮成立也省 256 lane。

结果是没有：

- 全域、除 `// % cdiv < ==` 外的全部 VALU 操作码、任意连线与常量、4 个仿射兼容输入键、
  任意奇数仿射输出：6,072 个模板全部 UNSAT。
- 第 0 轮 30 位定义域、8 个在该域上仿射的键：75,152 个查询全部排除。

所以，在这些自由度下，首段至少要 4 条指令；第 0 轮的输入范围也不能让它变短。
C1 那条异或省不掉的结论，从此前的具体形式族扩展到整个三指令语法。
可执行最好成绩仍是 864 cycles。
