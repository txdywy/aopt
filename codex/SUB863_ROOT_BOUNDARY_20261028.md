# 根节点重置边界的联合改写

**实际最好仍为 864 cycles，没有得到 sub-864 可执行程序。**
本轮研究跨轮边界，尝试删除每组一条向量操作。下列结论只覆盖明确的宏语法，
不证明整个哈希或整个内核最优。

## 1. 为什么研究这段

令 e 是第 10 轮最后一次 MAD 的结果，下一轮重新访问根节点。原程序的边界为：

```text
q = e >> 16
v = e XOR q
p = v XOR N
a = 4097*p+C0
N = raw_root XOR C5
C0 = 0x7ed55d16, C5 = 0xb55a4f09
```

这是四条指令。根节点整批共享，若三条程序可使用由根节点准备的参数，名义上
可省 32 个向量操作，即 256 lane；仍须扣除实际参数准备和调度成本。
搜索把这些参数全部放开，允许它们任意依赖固定的根节点，给这种方法充分余地。

本轮固定合法根值 `0x12345678`，因此 N=`0xa76e1971`。完整 32 位目标是：

```text
T_N(x) = 4097*(x XOR (x>>16) XOR N)+C0
```

## 2. 这里的 32 位输入确实有合法来源

初值、树节点虽然都是 30 位，但不能因此把该边界也缩成 30 位。
固定上述根、其他非叶节点全部为零，按未经修改的 reference 执行前十轮：

| 初值 | 叶层之前的值 | 高两位类别 | 选中叶子索引 |
|---:|---:|---:|---:|
| 0 | 74155005 | 0 | 2000 |
| 10 | 1293347200 | 1 | 1629 |
| 1 | 3112294280 | 2 | 1797 |
| 8 | 3840527551 | 3 | 1752 |

对任意 uint32 p，选择高两位匹配的这一行，并把该叶节点设为 `p XOR value`。
这个叶值必小于 2^30，且前十轮尚未读取叶层，所以不会改变此前的路径和值。
第 10 轮实际哈希输入便是 p。

前五段哈希由奇数乘法 4097、33、9，以及两个逐位可逆映射组成，因此是 uint32
置换。故其输出 e 覆盖全部 32 位。这是对固定根、参数仅依赖根的宏的覆盖论证；
不排除准备参数还读取其他树节点或更早状态的更大算法。

`prove_root_boundary863.py` 对 260 个 p 构造合法树和初值，直接用冻结 reference
检查上述路径、叶值与下一轮首 MAD。单元素构造可重复到全部 256 个独立元素。

## 3. 三条指令、一次右移的范围

`search_root_boundary863.py` 枚举一次 SHR16，加 MAD 与另一条 MAD/XOR/AND/OR。
MAD 两个乘数都可为运行时值，每条有任意私有常量，保留所有原输入旁路。
规范连线共 **967** 个：966 直接 UNSAT，唯一超时项延长后约 1.11 秒 UNSAT。
所有约束保留完整 32 位，没有缩短字宽后执行右移。

首 MAD 允许任意仿射、x²+C、x²+x；其他首 MAD 形式由这些形式包含。
常量移位源可直接预置，不能提供目标的高位到低位依赖；末尾非零右移不能产生
置换。死前缀可由中性 MAD/XOR 嵌入，不能产生遗漏的更短实现。

### 为什么单次常量右移只能是 16

T_N 的输出 bit0 随输入 bit16 翻转，输出 bit15 随输入 bit31 翻转；输出 bit0
不依赖输入 bit17..31。这些事实对任意 N 都成立，并有完整 32 位 SMT 检查。

- 若位数 s<16，右移之前最多一条无移位指令，低 s+1 位不能读到输入 bit16。
  最后无移位指令的 bit0 也就无法依赖它。
- 若移位直接读 x，或读一次逐位运算的结果，移位后 bit0 只可能读 x 的 bit s
  或常数。因此 s≠16 无法得到所需依赖。
- 剩下是右移读取首 MAD。偶数仿射与 x²+C 都丢掉输入 bit31，后续唯一移位
  之后再无操作能让它影响输出 bit15，矛盾。奇数仿射与 x²+x 在每个 s≥1
  都具有对角翻转：翻输入 bit s 会翻其输出 bit s。
- 对 s>16，这会给最终 bit0 引入可独立翻转的 x_s；所有其他未移位操作数的
  bit0 只依赖 x0。最终即使允许任意 Boolean 函数，也不能同时忽略这个独立
  干扰、又依赖 x16。该四项真值表矛盾另有 SAT 检查。

因此这一三指令语法中，任意 uint32 常量右移位数都归到 s=16；s≥32 为零，
s=0 则不提供高低位依赖。**这条归约不适用于四条程序或变量移位。**

正向查询在 N=0 和 N=2^31 时自动恢复已知的三条公式，均经全 uint32 反例查询
证明等价。后一个 N 对应合法的 30 位根值 `0x355a4f09`；因此结论不是“所有
根值都不能三条”，而是一般节点无法使用这一三条宏通用缩短。

## 4. 两次常量移位和一次 MAD

`screen_root_boundary_shifts863.py` 同时覆盖左、右移，独立或连续来源，以及
0..31 和 >=32 的全部常量位数。共 8,712 个参数组合；按对 32 个单比特基的
精确映射和两字段交换去重为 **4,002** 对移位函数。

把 q、r 在完整输入上实际算出，再允许输出是 x/q/r 的任意二次整数多项式：

```text
1, x, q, r, x², x*q, x*r, q², q*r, r²
```

这十个独立系数包含任意一个实际 MAD 的所有操作数选择。全部 4,002 个模
2^32 线性系统不相容，无超时、无幸存项。消元按最小 2-adic 赋值选主元，
没有在模环中非法除以偶数；每项都保留真实程序 `x*r+q` 的正向控制。

若最后一条是非零左移，低位固定；若为非零右移，高位固定，均不可能为目标
置换。零移位可嵌入前面的表达式，因此 MAD 的其他位置也已归约。
变量移位、除法、额外 live 字不在此范围。

### 不含 MAD 的剩余三条也可归约

目标输出 bit12 总随输入 bit0 翻转，此性质同样有完整 32 位 SMT 检查。
逐位运算和常量右移不能把较低输入位送到较高输出位，所以不含 MAD 的程序
还必须包含常量左移。若第三条是位运算，左移可精确写成乘 2^s 的 MAD，已被
第 3 节包含；若三条全是移位，输出只是一条移位链，没有混合数据的能力。

因此对这个固定合法根，三条 `{MAD,XOR,AND,OR,常量左移,常量右移}` 的一般
宏已排除；加、减、乘各是单条 MAD 的特例，也包含在内。它不涵盖变量位数、
比较、除法或额外 live 输入，更不是内核整体最优性证明。

## 5. 把前一轮末 MAD 也纳入

令 e=9*z+C4，C4=`0xfd7046c5`。原来的边界连同这次 MAD 共五条，新的四条
目标为 `T_N(9*z+C4)`。`search_root_affine863.py` 先检查三个具体形式：

```text
G*L(A*z+B)+H
G*(z XOR ((A*z+B)>>16))+H
G*((A*z+B) XOR (z>>16))+H
L(t)=t XOR(t>>16)
```

所有 A/B/G/H 任意。三项全宽必要样本 UNSAT，分别约 1.44、0.88、0.02 秒。
三个未固定系数的正向对照都自动得解，并经完整 32 位反例检查证明等价。

再以 `--joint --per-order 32` 对 111 个四指令顺序各抽 32 个图，允许一到三次
MAD、一次 SHR16，剩余为 XOR/AND/OR。**这 3,552 图是抽样，不是完整四条语法。**
首轮为 3,529 UNSAT、23 UNKNOWN；延长求解的最终状态保存在
`root_boundary863_joint_refinement.json`，原始 UNKNOWN 保留。补查得到 20 UNSAT、
3 UNKNOWN；最后三项的所有输入到输出路径都经过 SHR16，最多产生 65,536 个
不同输出，不能实现 32 位置换，因此由切点证书关闭。审计索引为
`root_boundary863_joint_audit.json`，仅将这 3,552 个抽样图关闭。

## 6. 控制与复现

依赖和研究源码指纹见 `root_boundary863_validation.json`。84 项完整 32 位
依赖/对角事实检查、4,674 个小字宽首指令模型的完整输入控制、680 次冻结 VALU
程序回放（5,440 个 full32 lane，含 600 个随机连接）均通过。随机连接还核对
Python 整数、NumPy、Z3 与冻结 ISA 四种执行结果。冻结模拟器、测试、提交与 864/865
备份未修改；局部宏控制不是新的完整内核成绩。
另有 11 项既有传输和模整数回归测试通过。

```bash
python -m codex.search_root_boundary863 --seconds 1 --workers 6 \
  --output /tmp/root-boundary.json
python -m codex.screen_root_boundary_shifts863 --output /tmp/root-two-shifts.json
python -m codex.prove_root_boundary863 --output /tmp/root-dependencies.json
python -m codex.search_root_boundary863 --joint --per-order 32 \
  --seconds 1 --workers 6 --output /tmp/root-joint.json
```

可执行最好仍为 864。尚未覆盖的更大连接、不同移位结构、变量位数、其他操作码
和额外 live 值仍需继续构造搜索与实际编译器验证。

读取它们；复用可能提供不同的改写空间。候选仍须推广到运行时根节点，并计入
参数准备、值的存活期与真实调度。
