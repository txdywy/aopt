This note preserves the **866-cycle** result and its research continuation.
The active root now executes **865 cycles**; see
[`SUB864_865_RESULT_20261021.md`](SUB864_865_RESULT_20261021.md).

or better has not yet been achieved.

The original nine official tests and 270 extended cases all pass at 866.
The extended set contains 256 full-width random seeds, eight ordinary seeds
and six boundary patterns. It executes after JSON serialization, checks all
architectural scratch writes and engine limits, and rejects runtime memory
accesses outside the original allocation. `tests/` and `problem.py` are unchanged.

This is the fixed `(10,2047,256,16)` workload, with initially zero indices and
the final-values-only contract. It does not return final indices. Browser
submission itself remains untested.

## What improved

The 40 bilinear records now occupy the consumed input-value region
`[2310,2534)`. Their block addresses reuse already-created input pointers.
All original input vectors are loaded before table writes, and final output
stores wait for the table reads that overlap their destination words.

The anchor reload uses one eight-word bank at `[2054,2062)`. Scalar constant
CSE removes redundant pointer/constant definitions while retaining every
contiguous register view required by the original ISA.

For a pair of uniform values A and B, four scalar copies of each form the
outer blocks of `[AAAA | AAAABBBB | BBBB]`. A known-mask FLOW select creates
the middle eight words. The two resulting eight-word windows are uniform
A and uniform B. A free standalone scalar producer can supply one of the
four outer words, so each root needs three copies. This transfers vector
initialization work to FLOW without using a runtime lookup table. The final
program uses nine paired broadcasts and one single broadcast of this kind.

These changes remove 114 arithmetic lane operations and eight FLOW operations
overall. Frozen-machine execution improves by two cycles. The standalone
payload contains ISA instructions only; runtime tree values and inputs never
enter the host-side generator.

## Further experiments

`research_sub864.py` also preserves separately selectable experiments:

- A different valid layout: X=(-60,-40), Y=(2310,2430), V=(4,16).
- STORE/reload broadcasts, FLOW literals and scalar coefficient generation.
- Direct scalar XOR with the first root, avoiding its vector broadcast.
- Complete buffer-pack ordering by consumer deadlines, with each pack's
  eight stores kept before its reload. Table/output epochs are retained.
- Parallel construction of buffer addresses, and ALU-to-FLOW constant moves.

The shared-layout, scalar-coefficient candidate reduced arithmetic work to
51672 and passed serial controls; one fully scheduled version also passed
20 full-width cases but took **871 cycles**. More arithmetic savings alone
therefore do not justify replacing the current result. Critical constant
availability, STORE/LOAD buffer chains and FLOW competition add startup or
body stalls. All research variants require a fresh schedule and frozen check.

For the current 51744-lane graph, even perfect arithmetic packing with the
standard head/drain allowance of 52+116 lanes requires at least 866 cycles.
A 863 design under that allowance needs at most 51612 arithmetic lanes,
132 fewer than the current graph. These statements concern this graph and
lowering family; they are not a global optimality proof. Public 864 research
is useful evidence of what another graph can do, not a locally reproduced score.

The best schedule, compiler inputs and result digests are preserved to make
future work cumulative instead of relying on temporary search state.

The final experimental sweep added header-derived address construction,
replaced selected scalar address calculations with literals, and transferred
priorities from the verified calendar with `warm_packet_modes.py` (over 99%
of operation identities matched). Two candidates had 51725 and 51697
arithmetic lanes and serial controls passed. Their best searched calendars
were 866 cycles; the packed-constant variant reached 867. These equal/slower
calendars were not promoted and do not replace the fully verified result.
The 51697 graph still requires at least 865 cycles under the same 168-lane
head/drain allowance, so it does not by itself offer a route below 864.

Four useful one-cycle header expressions fill early scalar slots without
adding operations: `14=7+7`, `246=256-10`, `294=cdiv(2054,7)` and
`2060=2054^10`. They are preserved behind `--head-fill`. Full correctness and
performance verification remains necessary for every new combination.

## Exact reproduction

Only Python's standard library and the original `problem.py` are needed to
use the standalone root file. To verify it:

```bash
python3.12 tests/submission_tests.py
python3.12 -m codex.verify_compact
```

To reconstruct the 866 program from readable sources and the saved calendar:

```bash
python3.12 -m codex.research_sub864 --relocate --banks 1 --cache-flow --pair-flow --flow=0xb55a4f09,-72,-52,2266,2378,1026,1027,1028,1029,3925396509,2899272192,0xfd7046c5 --prefix /tmp/aopt-866
python3.12 -m codex.packet_modes export --ir /tmp/aopt-866.ir.pkl --prefix /tmp/aopt-866-modes
cp codex/stride4_866_schedule.txt /tmp/aopt-866-modes.sol
python3.12 -m codex.packet_modes check --prefix /tmp/aopt-866-modes
python3.12 -m codex.emit_packet_submission /tmp/aopt-866-modes.json /tmp/aopt-866.py --cycles 866
```

The check validates all dependency edges, materializes instruction modes,
allocates scratch and runs 20 full-width cases. The emitted program digest
must equal the value above. Local pickle files in this process are compiler
intermediates, generated from this repository.

The saved schedule was found by `packet_mode_search.cpp`, 1000 iterations,
seed 953. Search is not needed for exact reproduction. For further search,
compile the C++17 source and write a different solution file, preserving
the verified calendar.

## Continued research: three-word FLOW broadcasts

At this stage the standalone root was the verified **866-cycle** version above.
The continuation added `research_bootstrap864.py`, `exact_packet_window.py`
and `shift_packet_calendar.py`. They are research tools, not runtime imports
of the submission. The CP tools require OR-Tools; the compiler and saved
calendar replay continue to use only the standard library.

A useful new lowering broadcasts a scalar with a three-word source block,
two scalar copies and one FLOW instruction. Select between two views of the
block shifted by three words, using the known mask `11100000`. Six result
words contain the scalar. The live uniform vector consists of the original
three words followed by the first five result words. The FLOW instruction
still writes its complete eight-word architectural result. All spans and
overwrite dependencies are retained by the allocator. This saves one copy
compared with the previous single-constant, four-word lowering.

The compiler also experiments with scalar construction and STORE/reload of
3, 4 and -2. Scalar users consume the scalar producer directly rather than
waiting for a vector reload. Earlier native broadcasts can be more valuable
than their arithmetic cost because they fill otherwise idle startup slots.

| Staged small constants, native 33 | 51677 | 1684 | 851 | 866 | 20 full-width cases |

The 51669 alternative uses 1289 scratch words. Its final packet-mode counts
are ALU=10317, VALU=5169, LOAD=1684, STORE=490 and FLOW=851. It did **not**
improve the score and was not promoted. The calendar and digests are saved
as `stride4_thirds_866_schedule.txt` and `stride4_thirds_866_result.json`.

Exact reproduction of that alternative, without repeating the search:

```bash
python3.12 -m codex.research_bootstrap864 --prefix /tmp/aopt-thirds --thirds --coefficients --sink 0 --literals 2 --literal-flow 7
python3.12 -m codex.packet_modes export --ir /tmp/aopt-thirds.ir.pkl --prefix /tmp/aopt-thirds-modes
cp codex/stride4_thirds_866_schedule.txt /tmp/aopt-thirds-modes.sol
python3.12 -m codex.packet_modes check --prefix /tmp/aopt-thirds-modes
```

The alternative program's compact-JSON SHA256 is
`46058eb2e78f7296993971344e3de308f8e48b640981e4e7b220e242a9d6a7b1`.
The saved search used seed 1091 and 1500 iterations.

The final resource-balanced alternative uses `--thirds --coefficients
--sink 0 --literals 0 --literal-flow 6`. It leaves one more LOAD and FLOW
slot than the 51669 alternative, costs two more arithmetic lanes, and also
executes 866 cycles (1302 scratch words, 20 full-width cases passed). Its
calendar and digests are `stride4_thirds_budget_866_schedule.txt` and
`stride4_thirds_budget_866_result.json`; the same reproduction commands work
with these flags and calendar. Its search used seed 1111 and 1200 iterations.

The exact scheduler passed a fixed-calendar control, including complete
dependency and capacity audits. Several bounded head-compression models
were proven infeasible; full-calendar shift models reached their time limit
with UNKNOWN status. These results neither prove a global lower bound nor
establish that 865 or 863 is impossible. All unresolved searches remain
separate from the measured production result.
The time-indexed repair model also proved the 51671 calendar cannot reach
865 while keeping its instruction modes fixed and moving each instruction
by at most one cycle. Wider movement is a different problem.

The original [challenge leaderboard](https://vliw-challenge.fly.dev/) was
checked again on 2026-10-21: Without Indices still had six tied 864 entries.
No new publicly reproducible sub-864 implementation was found in this pass.
