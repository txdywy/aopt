# 863 继续探索：C1 吸收的第三批检验与 FLOW 换算的上限（2026-10-27）

**可执行最好成绩仍为 864 cycles，本轮没有得到 863 程序。**

## 1. 与原输入组合的第一段形式

承接 `SUB863_REENCODING_RIGIDITY_20261027.md`：令 `a = 4097x + C0`，MAD0 可发
`w = μa + ν`（μ 奇），F 吸收 `m·y + c`（m 奇）。本批让第三条指令与原输入 x
组合，s 取 1..31：

```text
xxor: P = x XOR (w >> s)
xadd: P = x + k*(w >> s)
kx:   P = k*x + (w >> s)
wk:   P = k*w + (w >> s)      （k 可为偶数）
```

要求 `m·P + c == g19(a) XOR C1` 对所有 uint32 x 成立
（`affine_reencode_xmix863.py`）。

| 形式 | 原写法 300 秒 | 标准化写法 1800 秒补跑 | 合计 UNSAT |
|---|---:|---|---:|
| xxor | 30 | s=19：0.06 秒 UNSAT | 31/31 |
| xadd | 25 | s=20..24：2–22 秒 UNSAT；s=19 仍未解 | 30/31 |
| kx | 30 | s=19：32.8 秒 UNSAT | 31/31 |
| wk | 28 | s=19：194 秒，s=24、25：0.4 秒 UNSAT | 31/31 |

124 个查询中 123 个由 z3 直接判定 UNSAT；最后的 `xadd, s=19`
（`P = x + k*(w >> 19)`）见第 1.1 节，也为 UNSAT。**124 个查询全部无解。**

### 1.1 用外部 CDCL 求解器关闭最后一项

`cnf_cegis863.py` 先用 z3 把约束位展开并做 Tseitin 变换，再交给 pysat 中的
Kissat 4.0.4 或 CaDiCaL 1.9.5；未知数由具名布尔位拼成，便于解码候选并回到
CEGIS。流程先在已知情形上核对：xxor 阳性对照 3 轮得到 `μ=1, ν=0, m=1, c=0`
（34 秒），xxor 目标 s=19 为 UNSAT（3.9 秒）。

`xadd, s=19` 用 16 个样本、168,767 个子句，**Kissat 84.8 秒判定 UNSAT**。
z3 内置求解器在标准化写法下 1800 秒仍未完成，差别来自 SAT 引擎本身。

另有一个解析思路可作旁证：取 `x' = x + 2^31`，则 `T(x') = T(x) XOR 0x80001000`，
两边差分化为 `±4096·k ≡ ±4096·m' (mod 2^32)`；只要两个符号不完全相关，就得
`m' ≡ 0 (mod 2^19)`，与 m' 为奇数矛盾。完整证明“不完全相关”需处理
`μ ≡ 2^19−1 (mod 2^20)` 的边角情形，这里不展开，以求解器结果为准。

**标准化写法。** m 为奇数，所以 `m·P + c = T` 等价于 `P = m'·T + c'`
（`m' = m⁻¹`）。这样未知乘数只乘每个样本的常数目标值，位展开代价大幅下降：
xxor 的阳性对照（`x XOR (a>>19)`）在原写法下 300 秒未解出，标准化后立即得
`μ=1, ν=0, m=1, c=0`。另对 xadd、kx、wk 分别固定部分参数做对照，都解出预期
的 k（3、5、6）；只有 wk 在 μ、k 同时未知时 300 秒未解，属求解器在两个未知数
相乘时的速度问题，与编码无关。

## 2. FLOW 能否换回算术

在 864 图里，唯一能用 vselect 替代的算术是两遍的 d3 地址 `p3`、`p3'`：它们
只取决于三个奇偶位，可改为 8 选 1 选择树（7 条 FLOW，无 VALU），代替现在的
2 条 FLOW 加 1 条 MAD。每次替换为 (−8 lane, +5 FLOW)；8 个地址常量向量需先
构造（约 64 lane，全部组共享）。要净省 53 lane，需要
`8F/5 − 64 ≥ 53`，即至少 **73 条空闲 FLOW**。

在不增加算术的前提下，能腾出的 FLOW：

| 来源 | 数量 |
|---|---:|
| 863 周期下 FLOW 余量 | 2 |
| 尾部空闲 LOAD 窗口支撑的末轮“STORE 存右子节点”换存 | 约 3 |

后者是本轮新发现：864 日历中最后 14 条半选择 vselect 在第 836–851 周期，
而 LOAD 从第 843 周期起才有空槽。把末轮子节点选择改为“左子节点免费转置、
右子节点在被覆盖前 STORE 存出再 vload”，额外的 vload 要落在空槽里、又要早于
选择本身，只有第 844–851 周期的 6 条半选择（约 3 组）满足，每组省 1 条 FLOW、
不增加算术。合计只有约 5 条，远少于 73 条；其余释放 FLOW 的方法每条至少花
4 lane。因此 FLOW 这条路走不通。

其他算术都不能由 vselect 产生：`p5`、`p7`、`p9`、`p10` 依赖逐元素的前序地址，
奇偶位、节点异或、C5 恢复和哈希运算都不是“从已有向量中逐车道二选一”。

## 3. ISA 非常规用法清单

逐一核对后都不能带来合法的算术节省：

- 用哈希值作 vload 地址：越界；取高位作地址只会读到随机节点。
- 用奇偶位作 store 地址：只有 `mem[0]`、`mem[1]` 两个位置，元素间冲突。
- 变量移位：移位量来自哈希值时几乎总 ≥32，结果为 0。
- 按根节点值做 `jump_indirect` 专门化：随机树没有可保证的特殊结构。
- `halt` 提前结束、`pause`、调试槽、多核：要么输出不全，要么在冻结测试中无效。

## 4. 结论

C1 从第一段一侧被吸收的路径，本轮又排除了与原输入组合的四类形式（124 个查询全部 UNSAT）；FLOW 唯一的
算术出口需要 73 条空闲 FLOW，而无代价可得的只有约 5 条。仍未找到新原语。
