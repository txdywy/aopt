# 863 最后一次实验：构图选项全组合扫描（2026-10-27）

**可执行最好成绩仍为 864 cycles，本轮没有得到 863 程序。**

此前的配置扫描都是人工挑选的小组（32、42、122 组），构图器各开关之间的大部分
搭配从没一起试过。本实验用 `sweep_stage863.py` 系统扫描：每个组合都从头重建完整
指令图，再用 `scan_stage863.measure` 计算 863 的全部必要条件——算术 lane、前 6
周期与后 3 周期浪费下界、LOAD/FLOW/STORE 流下界。结果都是必要下界，不是成绩。

## 1. 扫描范围

| 部分 | 内容 | 组合数 | 有效 |
|---|---|---:|---:|
| A | 864 基线上逐个翻转 14 个布尔开关、逐个改动 9 个字符串/数值参数 | 45 | 40 |
| B | 随机同时改动 2–4 个上述选项 | 183 | 127 |
| C | `research_stage864.build` 内部写死的 14 个底层选项（指针打包、首部 C5 换读、标量移位、终端表、缓存向量、头部/原生打包、哈希与系数打包、stride16 等），单项及随机组合，并让 `small_stage` 取含 3 的值以满足部分选项的前提 | 146 | 56 |
| 合计 | | 374 | 223 |

无效组合是构图器不支持的搭配（断言、键或索引错误），逐条记录在结果文件中。

## 2. 结果

- **223 个有效组合中，周期下界 ≤ 863 的为 0 个。** A+B 的下界分布：864（109）、
  865（35）、866–874（23）；C：864（31）、865（11）、866–872（14）。
- 算术量最低为 51,639 lane（少 26），但需要关闭首部 FLOW 常量构造，FLOW 下界升至
  874。降低算术量的 72 个组合，无一例外地把 LOAD 或 FLOW 下界推到 ≥864。
- **在 LOAD、FLOW 下界都仍 ≤863 的 128 个组合里，最小有效预算为 51,830**
  （`tail_low=False, alu_layout=False`），比 863 的上限 51,780 多 50 lane，
  与基线 51,833 只差 3 lane。
- 意外发现：`header_pack='+:16'` 或 `'-:2'` 配合 `small_stage='3,4'` 时，尾部浪费
  下界从 116 降到 109–110；但算术量随之增加 1–2 lane、LOAD 下界升到 864，总预算
  51,828，没有净收益。

这里的首部界忽略 LOAD/FLOW 拥塞，只会低估浪费；真实情况只会更差。

## 3. 结论

在现有构图器能表达的全部 374 种配置中，没有任何一种满足 863 的必要条件；
能保持 LOAD/FLOW 可行的配置，算术加首尾浪费最少也比 863 多 50 lane。
这与资源影子价格的结论一致：凡是降低算术量的选项，都是用已经饱和的 LOAD 或
FLOW 换来的。
